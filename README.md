# LINE AI 智慧客服

客人在 LINE 官方帳號一對一聊天室提問，機器人依照 Google 試算表裡的 FAQ，用 Gemini AI 自動回答。

- 執行環境：Google Apps Script (免費，不需要自己的主機)
- AI：Google Gemini API 免費層 (不用綁信用卡)
- 知識庫：Google 試算表，**改答案只要改表格，不用動程式**
- 訊息服務：LINE Messaging API，全部使用回覆訊息 (reply)，不佔免費推播額度

## 運作方式

```
客人提問 → LINE → Apps Script ─┬─ 符合「固定回覆」關鍵字 → 直接回固定內容 (不呼叫 AI)
                               └─ 其他問題 → Gemini + FAQ → 回覆，並寫入「對話紀錄」
```

- AI 只根據 FAQ 回答，FAQ 沒寫的會請客人留電話，不會自己編答案
- 會記住同一位客人最近 10 則對話，6 小時沒講話就重新開始
- AI 思考時，客人會看到「輸入中」動畫
- 主模型塞車時，自動改用備用模型 (需設定 `GEMINI_FALLBACK_MODEL`)
- 目前只處理一對一聊天，群組訊息會略過

| 檔案 | 說明 |
|------|------|
| `Code.gs` | 機器人程式，整份貼到 Apps Script 編輯器 |

## 程式內的函式

| 函式 | 誰會執行 | 說明 |
|------|---------|------|
| `initSheet` | 你，**只在第一次**手動執行 | 建立試算表分頁與範例資料，已存在的分頁不會被覆蓋 |
| `setupCleanupTrigger` | 你，**只在第一次**手動執行 | 建立每日凌晨 3 點自動清理對話紀錄的觸發條件，重複執行不會建立多個 |
| `testAI` | 你，手動執行 | 不經過 LINE，直接測試 AI 回覆 |
| `cleanOldLogs` | 觸發條件每天自動執行 | 刪除超過保留天數的對話紀錄；想立刻清理也可以手動執行 |
| `doPost` | **LINE 自動呼叫** | ⚠️ 不要在編輯器手動執行，會出現 `Cannot read properties of undefined (reading 'postData')` |

> 💡 編輯器上方工具列的函式下拉選單預設停在 `doPost`，**按 ▶ 執行前一定要先切換到要跑的函式**。

## 試算表分頁

| 分頁 | A 欄 | B 欄 | 用途 |
|------|------|------|------|
| `設定` | 項目 | 內容 | `店名`、`聯絡電話`、`補充規則` (語氣、稱呼等額外要求)、`紀錄保留天數` (沒填預設 90 天) |
| `FAQ` | 問題 | 答案 | AI 的知識來源，寫越完整 AI 答得越好 |
| `固定回覆` | 關鍵字 | 回覆內容 | 客人訊息**完全等於**關鍵字時直接回，給圖文選單按鈕用 |
| `對話紀錄` | (自動寫入) | | 時間、userId、問題、AI 回覆，用來找出 FAQ 該補什麼；超過保留天數每天自動刪除 |

第一列都是標題，資料從第二列開始填。

## 操作流程

建議先開一個記事本，把過程中拿到的 key、token、網址暫存在裡面。每一步完成後再做下一步。

### 步驟 1：申請 Gemini API key

1. 打開 [Google AI Studio](https://aistudio.google.com/)，用 Google 帳號登入。
2. 第一次進入會跳出服務條款，勾選同意。
3. 點左側 **Get API key → Create API key**，專案選預設的即可。
4. 複製 `AIza...` 開頭的 key，貼到記事本。
5. 在模型清單找兩個模型，名稱都記到記事本 (以 AI Studio 當下列出的為準)：
   - **主模型**：flash 系列，例如 `gemini-3.8-flash`
   - **備用模型**：flash-lite 系列 (選填，主模型塞車時使用)

✅ 記事本應該有：API key、主模型名稱、備用模型名稱

> ⚠️ 免費層的對話內容可能被 Google 用來改善產品，且有每分鐘、每日請求數限制。**正式給客人使用前，請改用付費層或其他付費 AI**。

### 步驟 2：設定 LINE 官方帳號

**2-1 啟用 Messaging API**

1. 打開 [LINE Official Account Manager](https://manager.line.biz/)，點選你的官方帳號 (還沒有就先按「建立」)。
2. 右上角 **設定** → 左側 **Messaging API** → 按 **啟用 Messaging API**。
3. 第一次會要求建立 Provider (提供者)，名稱自訂。

**2-2 回應設定**

左側 **回應設定**：

| 項目 | 設定 |
|------|------|
| Webhook | **開** |
| 自動回應訊息 | **關** (改由程式的「固定回覆」分頁處理，避免重複回覆) |
| 加入好友的歡迎訊息 | 隨意，建議註明「本帳號由 AI 協助回覆」 |

**2-3 取得 Channel access token**

1. 打開 [LINE Developers Console](https://developers.line.biz/console/)，點剛剛的 Provider → 點你的頻道。
2. 上方切到 **Messaging API** 分頁。
3. 拉到最下面 **Channel access token** → 按 **Issue**。
4. 複製那串很長的 token，貼到記事本。

✅ 記事本應該有：API key、模型名稱、LINE token

> ⚠️ 要複製的是「Messaging API」分頁最下面的 **Channel access token**，不是「Basic settings」分頁的 Channel secret。

### 步驟 3：建立試算表與程式

> 程式必須從試算表裡開啟 Apps Script (綁定在試算表上)，才讀得到 FAQ。

**3-1 建立試算表**

1. 打開 [Google 試算表](https://sheets.google.com)，按 **＋ 空白試算表**。
2. 左上角把名稱改成「AI 客服知識庫」。

**3-2 貼上程式**

1. 試算表上方選單 **擴充功能 → Apps Script**，會開啟新分頁。
2. 編輯器裡的 `function myFunction() {...}` **全部刪掉**。
3. 用記事本打開本資料夾的 `Code.gs`，全選複製，貼進編輯器的 `程式碼.gs`。
4. 按 💾 儲存 (或 `Ctrl + S`)。
5. 左上角「未命名的專案」改名為「AI 客服」。

**3-3 設定時區與金鑰**

1. 左側 **⚙️ 專案設定**。
2. **時區** 選 `(GMT+08:00) 台北`。
3. 拉到最下面 **指令碼屬性 → 新增指令碼屬性**，從記事本複製貼上 (前後不要有空白)：

   | 屬性 | 值 | 必填 |
   |------|----|------|
   | `LINE_TOKEN` | LINE Channel access token | ✅ |
   | `GEMINI_API_KEY` | `AIza...` 那串 | ✅ |
   | `GEMINI_MODEL` | 主模型名稱 | ✅ |
   | `GEMINI_FALLBACK_MODEL` | 備用模型名稱，主模型回 503 / 500 時自動改用 | 選填 |

4. 按 **儲存指令碼屬性**。

**3-4 建立試算表分頁**

1. 左側點 **< >** 回到編輯器。
2. 上方函式下拉選單 (預設顯示 `doPost`) 切換成 **`initSheet`**，再按 **▶ 執行**。
3. 第一次會跳出授權視窗：
   1. **審查權限** → 選你的 Google 帳號
   2. 出現「Google 尚未驗證這個應用程式」→ 點 **進階** → **前往「AI 客服」(不安全)**
   3. 按 **允許**

   這是你自己的程式，所以 Google 會顯示未驗證，可以放心允許。
4. 下方執行記錄顯示「執行完畢」。
5. 切回試算表，確認多了 `設定`、`FAQ`、`固定回覆`、`對話紀錄` 四個分頁。
6. 把 `設定`、`FAQ`、`固定回覆` 的範例內容換成自己的 (之後隨時可以改)。

**3-5 設定對話紀錄自動清理**

1. 函式下拉選單切換成 **`setupCleanupTrigger`** → **▶ 執行**。
2. 會再跳出一次授權 (這次要的是「管理觸發條件」權限)，照 3-4 的方式允許。
3. 執行記錄出現「已建立每日自動清理觸發條件」。
4. 左側 **⏰ 觸發條件**，確認有一筆 `cleanOldLogs`、時間驅動、每日。
5. 保留天數到 `設定` 分頁的 `紀錄保留天數` 調整，沒填的話預設 90 天。

> 💡 如果是在加入自動清理功能**之前**就執行過 `initSheet`，`設定` 分頁不會有 `紀錄保留天數` 這一列，請自己在最下面新增一列：A 欄 `紀錄保留天數`、B 欄 `90`。不加也可以，會用預設的 90 天。

### 步驟 4：測試 AI

1. 回到 Apps Script 編輯器，函式下拉選單切換成 **`testAI`** → **▶ 執行**。
2. 看下方執行記錄：

   ```
   Q：你們幾點開門？可以退貨嗎？
   A：您好～我們營業時間是週一至週五 10:00-19:00 ...
   ```

✅ 出現 `A：` 加上依照 FAQ 的回答，就是成功。

❌ 出現「系統忙碌中」時，看執行記錄裡 `Gemini error (數字)` 的數字：

| 數字 | 原因 | 處理 |
|------|------|------|
| `400` / `403` | API key 錯誤 | 重新複製 key，確認前後沒有空白 |
| `404` | 模型名稱錯誤 | 對照 AI Studio 的模型名稱 |
| `503` | Google 端模型塞車，**不是設定問題** | 等幾分鐘再試，或設定 `GEMINI_FALLBACK_MODEL` |

**這一步沒成功前，不要往下做。**

### 步驟 5：部署成網頁應用程式

1. 編輯器右上角 **部署 → 新增部署作業**。
2. 左邊齒輪 ⚙️ → 選 **網頁應用程式**。
3. 設定：

   | 項目 | 設定 |
   |------|------|
   | 說明 | 自訂，例如 `v1` |
   | 執行身分 | **我** |
   | 誰可以存取 | **所有人** |

4. 按 **部署**。
5. 複製 **網頁應用程式網址** (`https://script.google.com/macros/s/.../exec`)，貼到記事本。

### 步驟 6：串接 LINE

1. 回到 [LINE Developers Console](https://developers.line.biz/console/) → 你的頻道 → **Messaging API** 分頁。
2. **Webhook URL** → **Edit** → 貼上步驟 5 的網址 → **Update**。
3. 開啟 **Use webhook**。
4. 按 **Verify** 若出現 302 錯誤，**不用理會**，這是 Google 轉址造成的，不影響使用。

### 步驟 7：手機實測

1. 在 Messaging API 分頁上方，用手機 LINE 掃 **QR code** 加好友。
2. 依序傳送以下訊息：

   | 傳送 | 預期結果 |
   |------|---------|
   | `營業時間？` | 依照 FAQ 回答 |
   | FAQ 沒有的問題，例如 `你們有賣手機嗎？` | 說要請專人確認、請你留電話，**不會亂編** |
   | `聯絡我們` | 立刻回 `固定回覆` 分頁的內容 |
   | 先問營業時間，再問 `那週六呢？` | 接得上前一句 |

3. 回試算表看 `對話紀錄` 分頁，確認有剛剛的問答。

🎉 全部正常就完成了。

## 搭配圖文選單

在 OA Manager 建立圖文選單時，按鈕動作設為「**文字**」，內容填 `固定回覆` 分頁裡的關鍵字。客人點按鈕就會回固定內容，不花 AI 額度，其他自由提問才交給 AI。

## 日常維護

| 想做的事 | 做法 | 需要重新部署？ |
|----------|------|---------------|
| 新增或修改 FAQ | 直接改 `FAQ` 分頁 | 不用 |
| 改店名、電話、語氣 | 改 `設定` 分頁 | 不用 |
| 新增選單關鍵字 | 改 `固定回覆` 分頁 | 不用 |
| 換 Gemini 模型 | 改指令碼屬性 `GEMINI_MODEL` / `GEMINI_FALLBACK_MODEL` | 不用 |
| 改對話紀錄保留天數 | 改 `設定` 分頁的 `紀錄保留天數` | 不用 |
| 修改 `Code.gs` | 見下方「修改程式後的更新方式」 | **要** |

建議每週看一次 `對話紀錄`，AI 答不出來的問題就補進 `FAQ`。

## 修改程式後的更新方式

在編輯器貼上新程式並儲存後，**一定要重新部署新版本**，否則線上跑的還是舊版：

1. **部署 → 管理部署作業**
2. 選取部署作業，按 ✏️ **編輯**
3. 版本選「**建立新版本**」
4. 按 **部署**

用這個方式更新，網址不會改變，LINE 端不需要修改。

> ⚠️ 不要用「新增部署作業」更新，那會產生新的網址，就要重新貼到 LINE 的 Webhook URL。

## 換成付費 AI

程式裡只有 `askAI()`、`callGemini()`、`parseGeminiResponse()` 這幾個函式跟 Gemini 有關：

- **換成 Gemini 付費層**：在 AI Studio 為該專案啟用計費即可，程式不用改。
- **換成 Claude 或 OpenAI**：改寫上述函式，其他程式不用動。

## 疑難排解

先到 Apps Script 左側 **執行項目** 查看紀錄：

| 狀況 | 原因 | 解法 |
|------|------|------|
| 手動執行出現 `Cannot read properties of undefined (reading 'postData')` | 執行到 `doPost` | 函式下拉選單切換成要跑的函式 (`initSheet` / `testAI`) 再執行 |
| 傳 LINE 訊息後完全沒有 `doPost` 紀錄 | LINE 沒呼叫到 Apps Script | 確認 Webhook URL 結尾為 `/exec`、Use webhook 已開啟、部署存取權為「所有人」 |
| `doPost` 失敗，錯誤含 `401` | LINE token 錯誤 | 確認指令碼屬性 `LINE_TOKEN` 是 Channel access token，前後無空白 |
| 回覆「系統忙碌中」 | Gemini 呼叫失敗 | 依步驟 4 的錯誤數字對照表處理 |
| 回覆「詢問人數較多」 | 超過 Gemini 免費層速率限制 (429) | 等一分鐘再試；常發生的話改用付費層 |
| 回覆很慢 (數十秒) | Gemini 塞車 | 主模型改用 flash-lite 系列 |
| AI 說不知道，但 FAQ 明明有寫 | 讀不到試算表 | 確認 Apps Script 是從試算表「擴充功能」開啟的，且分頁名稱是 `FAQ` |
| 改了程式沒生效 | 線上仍是舊版本 | 依「修改程式後的更新方式」部署新版本 |
| 對話紀錄沒有自動清理 | 沒建立觸發條件 | 左側 ⏰ 觸發條件確認有 `cleanOldLogs`，沒有就執行 `setupCleanupTrigger`；觸發失敗時 Google 會寄信通知 |
| 對話紀錄被刪錯 | 手動排序過 `對話紀錄` 分頁 | 清理是假設紀錄依時間由舊到新排列，**不要對這個分頁排序** |

## 安全注意事項

- `LINE_TOKEN`、`GEMINI_API_KEY` 只存在 Apps Script 指令碼屬性，**不要寫進程式碼或分享給他人**。
- 記事本裡暫存的 key、token 用完就刪除。
- 網頁應用程式網址任何人都能呼叫，不要公開張貼。
- `對話紀錄` 分頁會存客人的提問，可能含個資，試算表不要分享給不相關的人。超過 `紀錄保留天數` 的紀錄會每天自動刪除，但 Google 試算表的「版本記錄」仍可能看得到舊內容。
- token 或 key 外流時，到 LINE Developers Console / AI Studio 重新發行，並更新指令碼屬性。
